## 2. Scheme 语言简介与模块化思路

### Scheme 是什么

mini-Scheme 是一种极简的编程语言：几乎一切都写成 `(操作符 参数...)` 的形式——操作符写在最前面，括号决定运算顺序。例如 `(+ 1 2)` 表示 1 加 2。完整的语法规则见 `spec.md`。

### 一个解释器怎么运转

解释器就是"读懂一段程序文本，算出结果，再打印出来"的程序。流水线只有三步：

```
程序文本 ──读──→ 表达式 ──算──→ 值 ──打印──→ 结果
```

**模块化**就是把这条流水线拆成职责单一的小模块：读的归读的、算的归算的、打印的归打印的。这样每一步都能独立验证——测试挂了，你能立刻知道问题出在哪一步，也知道该让 AI 改哪个文件。怎么拆由你（和 AI）决定，建议见 §4。

## 4. 完成提示

### 建议的模块划分

参考流水线，常见拆法是：

| 模块 | 职责 |
|---|---|
| 词法 | 程序文本 → 词（token）列表 |
| 语法 | 词 → 表达式（嵌套的数据结构） |
| 环境 | 变量绑定表 + 指向外层环境的指针（词法作用域的关键） |
| 打印 | 值 → 文本 |
| 内置库 | spec §5 的全部内置函数，放进初始环境 |
| 求值器 | 表达式 → 值（心脏） |
| 入口 | 读文件/标准输入、逐行打印结果，即 `src/main.py` |

### 求值器的核心：evaluate 与 apply 互相调用

整个解释器的心脏是两个**互相递归**的函数：

- `evaluate(expr, env)`：求值一个表达式。符号 → 去环境查值；数字/布尔/字符串 → 原样返回；括号表达式 → 特殊形式（if/cond/define/lambda/let/quote/and/or/begin）按 spec §4 各自的求值顺序处理，其余是函数调用——先求值操作符和全部实参，再交给 apply。
- `apply(proc, args)`：调用一个过程。内置过程 → 直接调用；用户函数（闭包）→ 新建一层环境把实参绑到参数名上（外层指向函数**定义时**的环境），再回到 evaluate 求值函数体。

evaluate 遇到函数调用就调 apply，apply 执行函数体又调回 evaluate——想通这个循环，解释器就成了一半。

## 5. 本次实现（已完成）

### 文件与职责

`src/` 按上面那条流水线一对一拆分，每个文件只干一件事：

| 文件 | 职责 |
|---|---|
| `src/lexer.py` | 词法：程序文本 → 词法单元（注释/字符串转义/数字与布尔的识别） |
| `src/parser.py` | 语法：词法单元 → 表达式（点对链；`'x` 在这里展开成 `(quote x)`） |
| `src/values.py` | 运行时数据：点对、空表、符号（驻留）、字符串、过程 |
| `src/environment.py` | 环境：绑定表 + 指向外层环境的指针（词法作用域的关键） |
| `src/printer.py` | 打印：值 → 文本（真列表/点对/字符串转义，spec §8） |
| `src/standard_library.py` | 内置库：spec §5 的全部过程，按类别注册进初始环境 |
| `src/evaluator.py` | 求值器：`evaluate` 与 `apply` 互相递归 + spec §4 的九个特殊形式 |
| `src/cli.py` | 顶层循环：读文件/标准输入，每个顶层结果独占一行打印 |
| `src/main.py` | 入口：命令行参数解析、统一错误报告（含 `sys.path` 兜底） |
| `src/errors.py` | 统一的错误类型 `SchemeError`（带行列位置） |

设计上有两个刻意的选择：**表达式与引用数据共用点对链表示**（所以 `quote` 不需要
任何转换，`(equal? '(1 2) (list 1 2))` 天然成立）；**符号与字符串用不同类型包装**
（所以 `(eq? 'a "a")`、`(eq? #t 1)` 不会因为 Python 的类型相等而误判）。
